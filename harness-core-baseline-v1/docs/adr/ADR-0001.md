# ADR-0001：独立 Harness Core 的初始架构决策

- **状态**：Accepted（作为新仓库 v1 基线；后续变更必须新建 ADR）
- **日期**：2026-10-28
- **关联规范**：[`ARCHITECTURE.md`](../../ARCHITECTURE.md)、[`CONTRACTS.md`](../../CONTRACTS.md)、[`MIGRATION.md`](../migration/MIGRATION.md)
- **决策范围**：P0 / P1；部分 P2 边界先定语义，不承诺 P1 即实现全部行为

## 背景与约束

OtakuNeko 现有代码已具备结构化 Agent Loop、Dispatcher、Policy、Model Gateway、Run/Event Store、Checkpoint 和 SQL/BM25 Memory 的基础，但这些能力分布在 FastAPI、业务 Capability、ORM 和单体 Runtime 内部。五份 2026-10-28 的 Harness Foundation Audit 是**静态证据**，没有运行 CI、真实模型或跨进程恢复测试。

目标不是把旧 `backend/app/harness` 移入另一仓库，而是先定义独立通用 Harness 的契约，再借鉴旧代码的成熟算法、行为约束和测试案例实现它。

## 已采纳决策

| ID | 决策 | 理由与影响 |
|---|---|---|
| D01 | **建立独立仓库，Architecture-first Reconstruction**；旧代码只作实现参考 | 避免复制当前 Runtime/HTTP/ORM 耦合。禁止无合同的整包迁移。 |
| D02 | **Core/Ports/Adapters 单向依赖**；Core 不导入 Web 框架、业务 ORM、模型 SDK、旧后端 | 可独立安装/测试；CI 强制检查 import boundary。 |
| D03 | **单 Agent、单 Loop、单 Worker 起步** | 最小可验证闭环；P1 不宣称跨进程恢复或并发 Worker 安全。扩展留 ID/Port，不实现调度系统。 |
| D04 | **Runtime 是 Run 唯一状态转换者；模型只提出 `invoke|final` Decision** | 明确决策与权限边界；Transport、Loop、Provider 不直接修改 RunState。 |
| D05 | **Session/Run/Step/Event 分离** | 会话、执行、可观测操作和事件的生命周期不同；`thread_id` 为旧系统映射别名。 |
| D06 | **可信执行身份来自服务端；首版要求认证用户，匿名禁用** | 避免当前匿名请求可能消耗共享 Provider key 的条件性风险。未来匿名需显式 ADR/配额设计。 |
| D07 | **静态 Capability Registry + deny-by-default Policy** | P1 能完成真实的工具决策流程；Registry 不是授权，业务资源所有权仍由 Domain Service 检查。 |
| D08 | **真实外部写操作延迟至 P2 安全门禁后开放** | 先验证 durable intent/result、stable idempotency、approval 和 unknown outcome；Fake P1 不产生真实副作用。 |
| D09 | **Context 每次模型调用生成可追踪的 `ContextSnapshot`** | 原始 Transcript 与模型可见投影分离，预算、来源和压缩不应散在 Runtime 中。 |
| D10 | **Memory Service 独立，Core 只拥有 `MemoryReader` Port** | 读取可嵌入 Context；提取、合并、纠正、删除、画像和存储属于外部知识服务。 |
| D11 | **Memory Query-first，不要求向量数据库** | 当前主路径已有 SQL + BM25 实践；先结构化/关键词检索，语义索引须有 Eval 证据再引入。 |
| D12 | **RunState/Invocation facts/Checkpoint/Event 分离，逐步提供持久一致性** | P1 InMemory 明示不耐久；P2 将 Harness-owned state、intent/result、durable events 尽量置于同一事务边界。 |
| D13 | **事件区分 durable fact 与 ephemeral delta；禁止原始 reasoning 泄漏** | UI SSE 只消费安全投影；审计确认旧系统 `thinking_chunk` 可能持久化 reasoning，需要避免重现。 |
| D14 | **版本化 Contracts + Fake conformance + offline CI 是第一天的硬门禁** | 让安全、正确性和架构边界可自动验证，而非只靠文档与真实模型 benchmark。 |
| D15 | **业务 API 和 Agent API 并存** | 收藏/日程 CRUD 等确定性操作保留业务 REST；复杂推荐等进入 Harness；Hybrid 行为按明确用户动作/授权分流。 |
| D16 | **旧新运行按 Run owner 切换，不双执行副作用** | 只读/隔离数据可 shadow；Run owner 在创建时确定，cancel/resume/replay 一直路由给原 owner。 |

## 必须遵守的失败语义

- 不支持 provider capability → 明确错误，不假装兼容。
- 授权信息缺失/越权 → 拒绝；Memory、ToolResult、ModelDecision 不能修改 principal/tenant/allowlist。
- 审批中的参数或资源变化 → 重新审批或拒绝；审批结束不能视为资源授权自动永久有效。
- 外部效果可能已发生但结果未知 → `unknown_outcome`，进入待对账状态；不使用新幂等键盲目重试。
- 状态/Checkpoint 主版本不兼容 → 拒绝自动恢复并提供可诊断故障；不丢失 pending invocation。
- SSE 中断 → 可从 durable event replay，但绝不因此重新发起用户 Run 或重复写入。
- 缺少 usage/cost → `unknown/null`，不能填写 0 造成误导。

## P1/P2 能力分界

**P1 必须实现：** 受信身份、Session/Run/Step 基本契约、单 Loop、Fake A/B 模型、Context Builder、Fake MemoryReader、静态 Registry、Fake Tool Dispatcher、基础 Policy、RunBudget、InMemory Run journal、结构化安全 Event、离线 CI。

**P2 必须实现并验证后才能开外部写路径：** 持久化 Run/Invocation/Event、版本化 Checkpoint/恢复、审批与参数 digest、未知结果对账、Context compaction/Memory SQL 查询 Adapter、身份隔离、Trace 及断线 replay、故障注入测试。

> 注意：所谓“预留端口”不是创建大量无用的空文件。每个 P1 接口必须有 Fake 具体消费者和 conformance test。

## 尚未裁决的实现选项（不阻断 P0/P1）

| 议题 | 约束 | 最迟决策时点 |
|---|---|---|
| P2 事务持久化选型 | 必须支持 CAS、按 Run durable sequence、invocation intent/result 和可测试的恢复；不能依赖旧 ORM | P2 开发前补 ADR |
| P2 Worker/lease 规模 | P1 明确单 Worker；引入多 Worker 前必须有 fencing、取消传播和抢占恢复测试 | 多 Worker 上线前 |
| 后端 Adapter IPC | HTTP、进程内服务或其他方式均可；必须保持服务身份和资源授权，不共享私有 ORM | 接入真实 Backend 前 |
| Model Provider 第一实现 | 不固化在 Loop；至少 2 个 Fake 证明可替换；live Adapter 独立验证能力差异 | 首次真实模型调用前 |
| Memory 数据迁移策略 | 原系统保持数据 owner；保留来源、删除/保留政策和 scope，不在 Core 中复制用户知识表 | Memory Adapter 上线前 |
| 具体 Tokenizer/Compaction | 接口与预算不变量先固定，算法按 Provider 能力和评估迭代 | P2 Context 开发时 |
| 动态 Skills/Subagents/Workflow | 只保留 ID/关联扩展点，禁止提前引入大规模框架 | 出现可测试用例再立 ADR |

## 替代方案及拒绝原因

1. **在原仓库直接搬移旧 `harness/`**：快速但会复制当前应用特定模型和状态耦合；拒绝。
2. **全部通过 LLM 操作业务后端**：增加延迟、成本与副作用风险；确定性 CRUD 不需要 LLM；拒绝。
3. **P1 只实现模型和 Tools，P2 再加入 Policy/Context/Event**：未来需要推倒 Loop 与 Runtime；拒绝。
4. **Memory = 向量库 / Prompt 字符串**：不满足用户隔离、知识生命周期、来源和可纠正性；拒绝。
5. **一开始构建多 Agent/分布式 Event Sourcing**：没有当前验收需求支持，复杂度过高；拒绝。

## 评审和变更机制

- 任何改变执行权限、Run 状态、事件 replay、外部副作用恢复、Memory 作用域或依赖方向的 PR，必须**先更新 ADR/Contract fixture**。
- 每个 Batch 必须包含 Contract Test、权限/隐私回归和 Architecture Compliance Review。
- 旧代码冲突时，以经批准的 ADR 与 `CONTRACTS.md` 为准；开发者不得为了兼容而静默放宽约束。
- 本 ADR 是**新项目设计决定**，不是对旧系统已实现行为的认证。
