# 推荐候选渐进式召回设计

## 背景与目标

当前推荐链路能够读取用户收藏并生成中心化画像，但候选搜索把首个偏好标签同时作为关键词，并把前三个偏好标签作为 Bangumi 的多标签过滤条件。Bangumi 将多标签解释为“且”，因此查询容易为空；搜索又只请求最终展示数量，已看过滤和反感过滤后更容易没有候选。系统随后错误地返回“信息不足”，尽管用户已经有充分画像。

本设计的目标是优先保证能够推荐出作品，同时不推荐命中“明确反感”标签的作品。数据库读取、评分中心化算法和最终回答生成不在本次改动范围内。

## 选定方案

采用渐进式单标签召回、候选合并和本地排序：

1. 从 `favorite_tags` 中按现有偏好分数顺序取前三个标签。
2. 每个标签独立调用一次动画搜索，搜索关键词留空，只传一个标签，避免标签之间的“且”关系。
3. 每次搜索请求大于最终展示数量的候选池；默认召回量为 `max(max_candidates * 5, 20)`。
4. 合并各次搜索结果并按 subject ID 去重。
5. 硬过滤所有已看作品和命中明确反感标签的作品。
6. 按用户偏好匹配度、作品质量和原始召回顺序进行确定性排序，返回前 `max_candidates` 个候选。
7. 如果一个偏好标签的搜索失败，继续使用其他标签；只有所有搜索都失败时才返回“推荐服务暂时不可用”。搜索成功但过滤后为空时，返回“当前没有找到符合条件的新作品”，不得伪装成冷启动。

不采用一次传入多个标签的严格查询，也不采用完全取消反感过滤的全局热门兜底。

## 明确反感的定义

当前 `avoid_tags` 仅由相对评分基准低至少 `0.3` 分产生，但实际数据会把“动画”“TV”“年份”“制作公司”等结构性标签误判为反感标签。若将这些标签全部硬过滤，可能排除几乎所有候选。

画像输出新增 `strong_avoid_tags`，仅当标签同时满足以下条件时进入：

- `preference_delta <= -0.6`，与普通负偏好留出明确强度差；
- `weighted_count >= 3.0`，避免少量低分样本形成硬约束；
- 不是结构性标签。首版采用显式集合 `动画、TV、WEB、OVA、OAD、剧场版`，以及年份/月份正则 `^\d{4}(年(\d{1,2}月)?)?$`。制作公司标签不做自动猜测，仍按统计强度判断。

`avoid_tags` 保留作为负偏好信息和兼容字段；候选硬过滤只使用 `strong_avoid_tags`。普通负偏好不再一票否决，可在候选排序中降权。若旧画像不含 `strong_avoid_tags`，兼容逻辑使用空集合，不将旧 `avoid_tags` 自动升级为硬约束。

## 候选排序

每个候选计算确定性分数：

- 命中每个正向标签时，加入该标签 `preference_score` 对应的权重；
- 命中普通负偏好标签时，按负向 `preference_delta` 降权；
- 使用 Bangumi 评分作为轻量质量信号；
- 分数相同时，保持首次召回顺序，并以 subject ID 作为最终稳定排序键。

排序用于比较候选，不改变硬过滤规则。缺失标签或评分的作品仍可保留，避免数据不完整导致无结果。

## 数据流与可观测性

推荐 trace 为每次请求记录聚合统计，不记录用户的完整收藏或私密文本：

- 使用的偏好标签数量；
- 搜索调用次数、成功数和失败数；
- API 原始候选数；
- 合并去重后的候选数；
- 因已看被过滤的数量；
- 因明确反感被过滤的数量；
- 最终候选数；
- 最终空结果原因。

这样可以区分外部搜索失败、召回为空、全部已看和全部命中硬约束。

## 错误与空结果语义

- 没有评分或没有可用偏好标签：`cold_start`，提示用户补充评分。
- 所有外部搜索失败：`candidate_search_failed`，提示服务暂时不可用。
- 搜索成功但没有原始候选：`no_search_results`，提示未找到匹配作品。
- 原始候选存在但过滤后为空：`no_unseen_safe_candidates`，提示没有找到既未看过又避开明确反感的新作品。

## 测试与验收标准

使用 stub capability 完成自动化测试，不依赖真实 Bangumi 网络：

- 三个偏好标签产生三次单标签搜索，关键词不再使用偏好标签；
- 搜索参数不包含多标签“且”查询；
- 多路结果正确合并和去重；
- 单路失败不影响其他成功结果；
- 所有搜索失败才返回服务失败；
- 已看作品始终被过滤；
- `strong_avoid_tags` 始终硬过滤，普通 `avoid_tags` 只降权；
- 缺少标签或评分的候选不会被误删；
- 召回数量大于最终展示数量；
- 不同空结果原因返回准确文案；
- trace 统计准确反映召回和过滤阶段。

端到端验收要求：对现有本地用户画像（99 条最近收藏、68 条评分）执行“推荐几部动画”时，链路必须识别为非冷启动；只要任一偏好标签能召回未看且不命中明确反感的作品，就返回至少一个候选，不再显示“信息不足”。
